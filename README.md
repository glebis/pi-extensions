# pi-extensions

A collection of [pi](https://github.com/earendil-works/pi-mono) extensions — the
customizations that make pi a native participant in the rest of my environment:
answer panels, pane orchestration, Telegram, and project server management.

Each extension is self-contained: drop its file (or directory) into
`~/.pi/agent/extensions/` and pi loads it. Reload a running session with
`/reload`.

## What's here

### Interactive / agent behavior

| Extension | What it does |
|---|---|
| [`auto-continue.ts`](auto-continue.ts) | Detects responses truncated by the output-token limit (`stopReason: "length"`) and resumes them automatically, in-session. Core pi already recovers truncated messages that *contain tool calls*; this closes the gap for prose/code cut mid-stream. Rails: skips if messages are already queued, skips at ≥90% context (compaction owns that regime), caps consecutive continuations at 5. Command: `/autocontinue [on\|off]`. |
| [`prompt-stash.ts`](prompt-stash.ts) | Stash the prompt you're typing with `ctrl+s`, and get it back on the next `ctrl+s` or right after you send. With text on both sides it swaps instead of overwriting — nothing is lost. Footer shows a `stash: …` indicator. |
| [`cenno/`](cenno/) | Registers `ask_user` / `ask_sequence` so the agent asks through **cenno** floating macOS panels by default, instead of ending a turn with a plain-text question. Answers come back structured; a timeout is `{answered:false}`, never a yes. Also `/cenno-test`. |
| [`run.ts`](run.ts) | `/run` detects the current project's launch recipe (`package.json`, `Makefile`, `Procfile`, `docker-compose`) and starts it, with `status` / `logs` / `stop` / `restart`. Managed mode captures output into a ring buffer and kills the process group on session shutdown; `--pane` opens a real herdr tab that outlives the session. Checks the recipe's binary against `PATH` first, so a missing toolchain isn't just an opaque exit 127. |

### Orchestration

| Extension | What it does |
|---|---|
| [`herdr/`](herdr/) | Turns pi into a native participant of a running [herdr](https://herdr.dev) instance. Registers `herdr_overview`, `herdr_read`, `herdr_wait`, `herdr_dispatch` — plus a session manifest and `herdr-restore`, which reattaches pi sessions to panes that herdr restored as empty shells after a reboot. **Env-gated:** requires `HERDR_ENV=1`; registers nothing outside herdr. |

### Integrations

| Extension | What it does |
|---|---|
| [`telegram-telethon/`](telegram-telethon/) | Native Telegram tools wrapping the `telegram-telethon` Telethon CLI as typed pi tools: read/search/send/edit/forward, drafts, media download + transcription, channel publishing, and monitor-daemon control. Draft-vs-send safety rules are baked into the tool guidelines; ambiguous requests draft or ask instead of sending. Also `/tg <args…>`. |

## Design notes

Three conventions run through all of it:

**Env-gating over failure.** Extensions that need an external system register
their tools only when that system is present (`HERDR_ENV=1`, cenno's socket, a
located skill checkout). Outside that environment they're inert rather than
broken.

**Timeouts are not consent.** `ask_user` returning `{answered:false}` means the
panel timed out — it is never read as a yes. The same discipline applies to
sending on your behalf: explicit "draft" drafts, explicit "send" sends,
anything ambiguous drafts or asks.

**Clean up after yourself.** Short-lived bridge processes are always torn down,
Esc propagates through to the pending panel or blocked wait, and shutdown kills
process groups rather than orphaning servers.

## Install

```bash
git clone https://github.com/glebis/pi-extensions ~/.pi/agent/extensions
```

Or add a single extension by copying its file/directory into
`~/.pi/agent/extensions/`. Per-extension requirements and configuration are in
each extension's README.

## Requirements

Mostly macOS, and mostly `pi` itself. Specific extensions need:

- **cenno/** — the cenno app (`brew install --cask glebis/tap/cenno`), macOS
- **herdr/** — a running herdr instance, `HERDR_ENV=1`, the `herdr-task` wrapper
- **telegram-telethon/** — the `telegram-telethon` skill checkout, `python3`

`node_modules/` directories, where present, hold only symlinks into pi's own
bundled dependencies for editor/`tsc` support — pi resolves those packages
itself at runtime. They are gitignored.

`herdr-agent-state.ts` is also excluded: it's generated by
`herdr integration install pi` and overwritten on reinstall.
